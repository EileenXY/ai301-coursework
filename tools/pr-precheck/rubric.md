# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity | Plan context or plan.md scope, steps and deviation notes, compared with every changed hunk and the PR's description. | Each material addition or omission agrees with the plan or an explicit, reasoned deviation. The description accurately states what the diff implements and what remains; no silent expansion, omission, or contradicted completion claim. An explicitly disclosed partial outcome can pass. | required |
| Behavior evidence | Accepted reproduction and plan test plan, compared with candidate test evidence or test_evidence.md and Testing claims. | Recorded commands or concrete steps and observable before/after outcomes address the original behavior and the plan's relevant cases. Expectations are distinguishable from observations. Concrete reported outcomes for named controls are sufficient; do not require a separate transcript for every control. A remaining failure or omitted case is explicitly disclosed with its limitation and reason; unsupported success claims or only evidence of unrelated behavior fail. | required |
| Repository checks | Repo-facts required checks or live PR template/CONTRIBUTING.md, compared with test-evidence commands and results. | The repo's applicable checks have recorded executions and outcomes (a named command/test plus its concrete reported result is sufficient; raw terminal logs, exit codes, and formatter transcripts are not mandatory unless the repo explicitly requires them), including failures or no-tests outcomes; a documented environment blocker identifies the attempted command and its effect. A disclosed failure is not automatically a rejection. Merely saying tests pass, or never running the required checks without observable blocker evidence, fails. | required |
| Reviewable diff | Candidate unified diff and commit list, or git diff main...HEAD and git log main..HEAD, compared with issue and plan boundaries. | The issue's change is inspectable without unrelated edits, debug leftovers, dead/commented-out implementation, generated debris, or avoidable formatting churn. Disclosing unrelated cleanup does not make it necessary. Judge the hunks, not the number of commits. | required |
| Repository standards | Repo-facts template asks, contribution and AI policy, and issue-thread direction, compared with title and description; live mode also uses the course's explicit submission requirements. | Every stated applicable template section has substantive content or a justified N/A, the issue is referenced when required, and required disclosure and explicit maintainer direction are addressed. No boilerplate substitutes for evidence. Do not invent a template or AI policy where none is stated. For this course's pre-submission live draft, CI may remain unchecked because it only runs after opening, as the assignment explicitly directs. | required |

## Verdict rule

Return accept only when all required checks pass. Return reject if any required check fails or is unclear. Preferred checks, if later added, never change the verdict. Grade unclear when evidence cannot decide the condition; do not infer missing test success. Honest shortfalls may satisfy the stated conditions when supported and disclosed, but do not excuse unrelated edits, fabricated evidence, missing mandatory disclosure, or silent plan drift.
